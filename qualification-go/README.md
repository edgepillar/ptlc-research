# Core-verifier compatibility qualification

Offline verification only. This module pins `btcec/v2 v2.3.2` and `x/crypto v0.1.0`, matching the inspected [PTLC proposal's dependency versions](https://github.com/zenon-network/go-zenon/blob/8ed1ca1e012a2c7a2e9ecc456fb82bdef75a4a18/go.mod). These historical dependencies are test subjects, not a production dependency recommendation.

The tests verify public completed signatures regenerated by the Rust harness, reject changed messages/signatures/encodings, and independently recompute the synthetic Zenon message as SHA3-256 of a 32-byte entry ID followed by a 20-byte destination. Modified IDs, destinations and a Keccak digest are negative controls. The selected dependency's BIP340 parser/verifier is the same version used by the proposed contract; no node, account validation, VM, RPC or contract execution is run.

The official BIP340 public corpus contains 19 vectors. This old Go verifier matches the first 15 vectors, whose messages are 32 bytes, and rejects all four newer variable-length positive vectors. That restriction matches the contract's digest width but is **not complete current BIP340 message-length conformance**. Both Rust candidates accept the official variable-length positives.

Stage 3 also checks both completed signatures in `qualification/fixtures/nonce_rounds.json`, rejects message/signature mutations, and parses the eight compressed points in its four distinct public nonces. This verifier does not check partial signatures, adaptor pre-signatures, application context hashes, or nonce freshness. All four top-level tests passed in the Stage 3 offline run; see the [validation report](../docs/STAGE3_VALIDATION.md).

Stage 9 adds a fifth top-level test over `qualification/fixtures/authentication.json`. It independently reconstructs the domain-separated 32-byte envelope message and verifies both public authentication signatures, including the envelope with an invalid inner Zenon signature. Changed payload and wrong sender key reject. This is independent fixture verification, not peer enrollment, a reusable authentication service or a contract test. See the [Stage 9 report](../docs/STAGE9_VALIDATION.md).

Dependency acquisition needs network access once. With Go 1.23.12 and the cache populated:

```sh
go mod download all
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go test -mod=readonly -count=1 -v ./...
```

Tests read public fixtures in sibling directories; run from this module's directory. No signing keys, seeds or adaptor witnesses are in the exported fixture. Synthetic test scalars in the Rust harness are deliberately public test inputs and must never be used with funds.
