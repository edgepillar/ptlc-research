# Retained full capsule and source-read binding

This separate offline construction binds actually retained public synthetic
originals and charged UNKNOWN work to an independently prepared NoM read. It
implements no authenticated source, consumer nonrollback checkpoint, observer,
worker admission or recovery action. Application/core remain **NO-GO**; all
results remain **HOLD** with action **NONE**.

## Requirement and selected construction

Before pairing a read with retained custody, require complete fixed terms and
the exact original envelopes from that custody. A retained public completion
alone cannot supply a missing original. A source label, known fixture, diagnostic
reply or later query cannot create missing output or clear possible disclosure.
Bind the exact capsule and its charged work separately from the observer's
retention selection; the two stores have different schemas and counters.

`bind_read_query(retained, query)` requires exact `CapsuleView` and `NoMReadQuery`
objects. It refuses all three admitted cuts lacking the long original, including
the result-present/original-absent cut. In the complete state, both original
envelopes must equal the exact retained long and remote short bytes; full terms
must agree and the read must retain possible disclosure. No missing envelope is
constructed, public signature is verified or file is opened.

The immutable binding contains the full existing canonical query bytes, capsule
digest, raw journal digest, journal head/sequence, partial selection digest,
verification context and every persisted charged UNKNOWN ordinal. The caller
must retain the complete originals independently; hashes do not replace custody.
The frozen capsule, partial HOLD and authority-query formats remain unchanged.
Their earlier review limits are not promoted by this separate construction.

The work-scope digest uses `ptlc-nom-capsule-read-work-scope-v1`, a zero byte and
the existing canonical object containing the complete verification context and
exact remote-short digest. Query challenges, source revision/incarnation,
observer-retention pins and result/original progress cannot mint a new scope.
Newly selected charges alter the binding and preserve earlier ordinals. This
scope is a research identifier, with no authenticated resource enrollment,
global budget, execution receipt or deduplication service.

The binding digest uses `ptlc-nom-capsule-read-binding-v1`, a zero byte and the
complete canonical binding. `parse_binding` requires exact independently
retained bytes; it never selects its own expected state from incoming labels.
The maximum frame is 128 KiB with twelve JSON levels, using the unchanged strict
ASCII codec. Extra or duplicate fields, alternate numeric/hex encodings,
oversized wire and cross-binding substitutions refuse.

## Separate retention and claim semantics

The existing read's `consumer_selection` continues to describe independently
asserted observer-retention pins and an opaque external checkpoint. It is not
derived from the recovery journal and is not authenticated here. The binding
keeps journal pins in separate fields. A lower observer counter cannot erase
charged work; accepting its shape establishes neither currentness nor a trusted
restoration. Same-counter equality would establish neither correspondence nor
nonrollback protection.

A separate claim binds the outer binding digest and exact raw bytes of the
unchanged authority claim. The inner query digest, challenge, checkpoint and
eleven evidence obligations must match independently. Supported, unknown,
contradicted and unavailable labels retain their distinct coverage summaries.
Even complete zero-evidence claims are forgeable. An old claim with another outer
binding refuses, but an attacker can rewrite an unsigned outer digest and match
again when the inner read is unchanged. This successful unsafe control remains
HOLD/NONE and demonstrates the missing source authenticator.

Coherently restoring a capsule, query, binding and claim together still matches.
Fresh challenges can bind old positions. No latest chain, canonical fork,
authorized consumer incarnation or external nonrollback state is selected.
An actual authenticator must independently provision the source and verify the
entire binding at the precise protected-use boundary; signing a prior read alone
does not resolve stale use or unknown worker completion.
