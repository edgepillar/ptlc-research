# Selected NoM uncertainty hold

This offline comparison follows the two selected [public rollback refusals](NOM_ROLLBACK_REFUSAL.md).
The immutable pure `offline_session/nom_uncertainty.py` selection keeps exact
original operations, prior public evidence, possible disclosure and charged work.
It always returns `HOLD`, recovery action `NONE`, and application/core `NO-GO`.

The zero-pop refusal preserves selected M3 state; the one-pop refusal leaves an
M2 prefix with typed source uncertainty. Neither outcome authenticates a source,
establishes current funding or completes the target rollback. This comparison
binds each complete old corpus record by digest and retains its exact failure
object as an **unauthenticated research claim**. The existing corpus qualifier
independently checks complete records. Native execution is a separate required
check; the new pure comparison runs no Go.

The authority query retains complete fixed terms, both exact synthetic original
envelopes, independent network/checkpoint/consumer selections, candidate digest
and all eleven obligations. Its synthetic momentum contexts are **not composed
with the rollback corpus contexts**. Neither context is a canonical live chain.
Prior synthetic inputs and public-source pins stay unchanged. Original digests
use a separate SHA256 domain and are not account-block or transaction hashes.

## Retained comparison state

Prior work binds unique synthetic attempt identifiers to the exact long or short
original digest and an `UNKNOWN`, `COMPLETE` or `FAILED` outcome. All entries
remain charged. The selection permits sixteen prior work entries, eight prior
evidence items of at most 512 bytes, and eight exact claims in each class. The
canonical state is bounded at 128 KiB and twelve JSON levels. These are finite
comparison allowances, not an application resource policy.

Source claims are framed against the exact selected query. Unavailable,
contradicted, unknown and complete supported claims retain the same originals,
evidence, disclosure bit and charges. Even an all-supported reply with zero
evidence digests supplies no recovery permission. Exact replay returns the same
immutable object, adds no work and supplies no freshness. Malformed or exhausted
retention refuses with the prior object unchanged; no exception permits a
replacement operation.

Exact local comparison rejects charge removal, rewritten outcomes, evidence
omission/reordering, original replacement and lost possible disclosure. It needs
an independently retained object. A coherent older object with matching old
bytes still passes, demonstrating the missing external restore fence. In-memory
immutability and hashes cannot authenticate caller-selected charges, prove
custody or preserve history after process death.

## Selected finite counterexamples

Three policies run twenty-eight schedules and 136 transitions each: 84 schedules
and 408 transitions total. The domain includes both refusal cases, ten ordered
update/entry shuffles per case, exact replay, coherent old copies and exhausted
prior work.

`forget-on-unavailable` erases charges and permits new abstract entries, including
after sixteen prior entries. `release-on-supported` permits untrusted entries
after a forgeable complete reply. `retain-hold` has no new abstract entry or charge
erasure in this finite domain. Coherent old copies still lose later evidence.
Abstract entries never invoke a worker or sign anything. No result establishes
unbounded safety, liveness or funded recovery. Partial execution reports
`complete:false` and exits with two.

## Independent requirements

No journal, observer callback, RPC, node, clock, signer, recovery worker or
broadcast path is connected. This module is not accepted by the recovery
journal's explicit trusted observation callback. Existing journal, source and
cryptographic paths remain unchanged.

A usable design needs independently authenticated current source evidence,
execution/account provenance, funding/live-entry revalidation, a consumer restore
fence and atomic admitted work. Durable retention and interrupted-work
reconciliation require separate review before journal composition. No API
releases this hold from unauthenticated labels; a future release protocol remains
unselected. See [authority obligations](NOM_AUTHORITY_CONTRACT.md),
[reference recovery](NOM_FIXED_RECOVERY.md) and [validation](NOM_UNCERTAINTY_HOLD_VALIDATION.md).
